## 一、怎么跑起来

1. Unity Hub 打开 `E:\Unity\Klein`，等编译完成
2. 打开场景 **`Assets/_Project/Scenes/Title.unity`**（Build Settings 首位），按 Play
3. 流程：**开始界面** →点「开始游戏」→ **选人界面**（水 / 火 / 木 三选一）→ **游戏场景**

> 想直接进游戏调试：打开 `Whitebox.unity` 按 Play 即可，此时本命元素默认取水。
> 也可在游戏内按 `F1` 临时切换元素。

### 三个场景

| 场景 | 内容 | 说明 |
|---|---|---|
| `Title.unity` | `Main Camera` + `TitleScreen` | 标题 + 「开始游戏」按钮；顺带显示上次的选择 |
| `Select.unity` | `Main Camera` + `ElementSelectScreen` | 三张元素卡，各列出该元素的两条主要反应；有「返回」 |
| `Whitebox.unity` | `Main Camera`(+`CameraFollow`) + `GameBootstrap` | 游戏主体 |

三个场景本身都只有一两个对象：**墙体、门、房间、元素地形、玩家、怪物、法术、掉落、HUD 全部在运行时由代码生成。**

选中的元素通过静态类 `GameSession.SelectedElement` 跨场景传递（场景切换不会重置静态字段），
`GameRuntime` 生成玩家时把它写进 `PlayerStats.Element`。

### 编辑器菜单

| 菜单 | 作用 |
|---|---|
| `Klein/生成数据资产` | 把代码默认数值落盘成 SO 资产 |
| `Klein/生成全部场景（开始/选人/游戏）` | 重建三个场景并按顺序写进 Build Settings |
| `Klein/从 Art 文件夹自动填充贴图` | 扫描 `Assets/_Project/Art/`，文件名 = VisualKey 的图自动挂到 SpriteSet（详见「美术资源替换」一节） |

数据资产位置：`Assets/_Project/Resources/Klein/`（23 个 `.asset`，Inspector 可直接调数值）。
两个菜单合起来等价于批处理入口 `Klein.EditorTools.WhiteboxBootstrap.RunBatch`。

### ⚠️ 关于 OnGUI 按钮

本工程的 Active Input Handling 是新版 Input System，**IMGUI 的鼠标事件在这种情况下不可靠**，
所以 `GUI.Button` 一个都没用。`KleinUi.Button` 用 Input System 读到的指针位置自己做命中测试
（`ScreenToGui` 负责把"左下原点"的屏幕坐标翻成"左上原点"的 GUI 坐标）。
开始界面、选人界面、法术背包、结算面板里的按钮全部走这一套 —— `T21` 专门盯着这个转换，
因为一旦漏了 y 翻转，症状就是"点击位置上下镜像"，很难一眼看出来。

### 操作

| 输入 | 行为 |
|---|---|
| **鼠标右键点地** | **唯一的移动方式**。无障碍径直直线走到目标点；有障碍退回 A* 自动寻路（详见下节） |
| 鼠标位置 | 决定施法方向与角色朝向 |
| **鼠标左键 / 回车** | 菜单、法术背包、结算面板里的「确认」 |
| **`Q W E A S D`** | 六个法术槽（v2 已明确是六个键） |
| **`空格`** | 使用主动道具 |
| **`Shift`** | 切换主动道具 |
| **`B`** | 打开法术背包（点背包里的法术 → 再点槽位装配） |
| **`F1`** | 临时切换玩家当前元素（水→火→木），选人场景之外的调试快捷键 |
| **`R`** | 重建当前层（调试用） |

> ⚠️ **`WASD` 已不再控制移动**（按需求移除）。A/S/D 与 Q/W/E 一样，只用于施法。

### 移动逻辑

```
右键点地 → 记下目标点
   ├─ 目标格可走 且 与角色之间直线无遮挡  → 径直朝【点击的精确点】直线移动
   ├─ 有遮挡（墙 / 关着的门 / 柱子）      → A* 绕行到【距点击处最近的可走格】
   └─ A* 也不可达（门锁着 / 点在地图外）   → 不接受指令，保持不动
```

- 直线判定走 `NavUtil.HasLineOfSight`：沿线每 0.15 格采样，除中心线外还向两侧各偏移一个**角色半径**再采一遍——否则贴墙的擦边路线会被误判成通畅，人会卡在墙角。关着的门同样算障碍。
- 直行途中若被墙角或怪物卡住（0.25 秒内位移不足 0.12 格），自动改用 A* 试着绕过去，实在绕不过就停下（`PlayerController.CheckStuck`）。
- 寻路模式不做卡住判断——物理推挤造成的短暂停顿不该中断指令。
- Gizmos：直行是**绿色**直线 + 目标球，寻路是**青色**折线，在 Scene 视图里能直接看到判定结果。

### 技术取舍

- **零资产依赖**：所有占位贴图用 `SpriteFactory` 在运行时生成（1 张 16×16 贴图 = 1 格 = 1 单位）。美术进场时只需把 `SpriteRenderer.sprite` 换成真图。
- **不用 Tilemap**：元素地形以格为单位存在 `ElementGrid`（字典 + 每格反应次数）里，视觉是独立 SpriteRenderer。比每帧 Raycast 便宜，也方便做"蒸汽扩散"这类扩展。
- **不用 Canvas/TMP**：HUD 走 `OnGUI`，并用 `Font.GetOSInstalledFontNames()` 挑系统里的微软雅黑/黑体，避免内置字体没有 CJK 字形导致中文变豆腐块。
- **不依赖物理层**：弹体撞墙查 `LevelGrid`，命中判定用 `OverlapCircleAll` + 组件筛选，免去配置 Layer 的步骤。
- **组件自动装配**：`GameBootstrap` 只挂一个组件，其余全部 `AddComponent`，所以场景文件极小（7.5 KB）。

### 已实现的关键机制

**关卡（以撒式）**
- 5×5 网格上随机生长 10–14 个房间，**一步只在"还有空邻居"的房间上生长**，不会因随机方向连撞墙而提前卡死
- 特殊房一层各 1 个（商店/法术/宝箱/BOSS），**BOSS 房取距起点 BFS 最远者**（近似 v1 的"道路尽头"语义）
- 门锁规则：**玩家所在那一侧房间清空后开启**（以撒规则：本房未清空不能离开）
- 房间按需生成（首次进入才刷怪），单房超时 90 s 追加一波
- BOSS 击败 → 生成传送门 → 下一层；第 5 层后判定通关

**怪物编辑器**——字段严格照抄策划案 10 项
`血量 / 移速 / 射速 / 子弹速度 / 伤害 / 同房间最大存在数 / 掉落物种类 / 掉落物数量 / 掉落物权重 / 移动方式`
四个原型精确覆盖案中列出的 4 种画像 + 1 个 BOSS：

| 原型 | 画像 | 血量 | 移速 | 射速 | 弹速 | 伤害 | 同房上限 | 移动方式 |
|---|---|---|---|---|---|---|---|---|
| 重甲兵 | 近战·慢速高血量单体 | 60 | 2.0 | — | — | 12 | 3 | 持续移动 |
| 虫群 | 近战·慢速低血量群体 | 18 | 2.5 | — | — | 5 | 8 | 持续移动 |
| 术士 | 远程·不移动低弹速高射速 | 35 | 0 | 1.5/s | 6 | 8 | 4 | 不移动 |
| 游猎 | 远程·低血量高弹速低射速 | 25 | 1.5 | 0.4/s | 14 | 14 | 4 | 间歇移动 |
| 元素之主 | BOSS | 600 | 2.0 | 1.2/s | 7 | 12 | 1 | 持续移动 |

**元素系统**——3×3 矩阵全部落地

| 法术＼地形 | 水地形 | 火地形 | 木地形 |
|---|---|---|---|
| **水法术** | 地形次数 +1 | **穿透 + 伤害 ×2** | **腐烂区域** 减速 ×0.5，r2.5，5s（**只对敌方**） |
| **火法术** | **蒸汽区域** 8 伤/0.5s，r3，6s | 地形次数 +1 | **爆炸** 40 伤，r2.5 + 击退 |
| **木法术** | **回血区域** 5 血/0.5s，r2.5，6s | **穿透 + 灼伤** 5%/s（BOSS 1%），4s | 地形次数 +1 |

- **地形以「块」为单位**（详见下节）：形状不规则，但反应时**整块共享一份次数**
- 每块地形初始 **3 次**反应次数，**每 5 秒自动 +1 次，上限 5**；同元素法术撞同元素地形额外 **+1**
- 冷却：单次法术与**同一块地形**每 **60 帧**最多 1 次
- 蒸汽 / 回血 / 爆炸对**区域内所有单位**生效（含怪物——按策划案原文，见待拍板 Q2）
- **腐烂区域例外：只减速敌方单位，不减速玩家**

**决策 Q1 的落地**：法术固有元素与玩家当前元素**两者叠加**。弹体带 `ElementMask`，仲裁时**先试固有元素、再试玩家元素**，一次命中最多产生一次反应、最多消耗该地块 1 次次数。

### 地形单位：整块（TerrainBlob）

地形不再按"格"结算，而是**一整块**：

| 方面 | 行为 |
|---|---|
| 形状 | 用**随机化 BFS** 生成，每步有概率不长出去，边界天然凹凸不平（不是圆盘/方块） |
| 大小 | 每块 14–61 格；每个房间 1–3 块 |
| 次数 | **整块共享一份**。初始 3，**每 5 秒自动 +1，上限 5**，耗尽后变灰、等回充 |
| 反应 | 一次法术撞上这块地形的**任意一格**，整块只触发一次、只消耗 1 次 |
| 冷却 | 按**块**计（60 帧），不是按格 |
| 区域中心 | 以地块的**质心**（吸附到最近的块内格）为中心生成，保证落在地形上 |
| 观察 | HUD 左上角实时显示脚下地块的元素与剩余次数 |

> 这一条修掉了一个隐蔽问题：旧实现里同一块视觉上连续的地形，每格各自持有 3 次次数，
> 于是**一次弹体扫过去会消耗好几次**、而且同一个斑块的不同格子反应冷却互不影响。
> 现在 `T15`/`T17` 分别用"逐格打"和"一个弹体横穿 6 格"两种方式把它钉死了。

## 四、测试抓到的 3 个真 bug（已修）

这三个都是实现缺陷，不是测试写法问题：

1. **门洞行号算错**（`FloorGenerator.BuildDoors`）
   "向下"方向的门用了 `yMax`（那是**上方**的墙），实际应为 `yMin - 墙厚`。
   后果：部分种子下房间在网格上真的连不通，玩家会被卡死。
   现在 `T11` 跨 **40 个种子 / 482 个房间**做洪水填充回归。

2. **弹体对同一格地形重复触发反应**
   反应冷却按帧计（60 帧），而帧率越高、弹体在同一格里停留的帧数越多——冷却一到就对**同一格**重复触发，实测一次把 3 次次数全部打光。这是**帧率相关的行为差异**。
   修法：给每个弹体记录"已反应过的格子"，**一个弹体对一格地形最多反应一次**；60 帧冷却退化为跨弹体的限流。

3. **静态对象池无法销毁**
   `EnemyFactory` / `Projectile` / `Pickup` 的静态根节点只置空引用、不销毁 GameObject，导致切层与重开局时残留怪物/弹体持续存在（测试里表现为前一个用例的怪物挡住了后一个用例的弹体）。
   修法：`Reset()` 真正销毁根节点。

> 另外，`T13/T14` 第一版也失败过一次，但那次是**测试假设错了**、不是实现错了：
> 房间中轴正好对准门洞，而起点房已清空 → 门是开的，所以"直线"其实是**穿门而过**，
> 判定为通畅完全正确。改成针对"非门洞的实心墙格"后通过。
> 这条反直觉的情形已经写进 T13 的注释里。

## 五、美术资源替换

**所有单位/物件的贴图都走同一套替换机制**：优先用配好的正式美术，没配就用运行时生成的占位色块。
所以现在可以一张图都没有，后面也可以一张一张往里替换，**不需要改代码**。

### 怎么换图（3 步）

1. 把图丢进 `Assets/_Project/Art/`（可以带子文件夹）
2. **文件名改成要替换的槽位名**（下表），例如 `Player_Body.png`、`Wall.png`、`Terrain_Water.png`
3. 执行菜单 **`Klein/从 Art 文件夹自动填充贴图`**

第 3 步会扫描 Art 文件夹，按文件名匹配槽位挂到 `Resources/Klein/SpriteSet.asset`；
**如果图片没被导入成 Sprite，它会自动改 TextureImporter 设置并重新导入**——
也就是说直接从资源站拖 png 进来就能用，不用手动改导入设置。

也可以不用菜单：直接在 `SpriteSet.asset` 的 Inspector 里手动拖图。

### 两条替换通道

| 通道 | 位置 | 适用 |
|---|---|---|
| **全局贴图表** `SpriteSet` | `Resources/Klein/SpriteSet.asset` | 玩家、墙、门、地形、区域效果、掉落物、宝箱、传送门等**全局唯一**的图 |
| **逐单位贴图** | `EnemyDefinition.BodySprite`、`ItemDefinition.IconSprite`、`SpellDefinition.ProjectileSprite` | 怪物/道具/法术**每个都不一样**的图。留空则回落到全局表，再回落则用占位色块 |

优先级一律是：**逐单位贴图 → 全局表 → 运行时占位图**。

### 槽位清单（文件名 = 枚举名）

| 分类 | 槽位 |
|---|---|
| 玩家 | `Player_Body` · `Player_Aim` |
| 通用单位 | `Enemy_Body` · `Projectile_Player` · `Projectile_Enemy` · `Barrier` |
| 地形 | `Terrain_Water` · `Terrain_Fire` · `Terrain_Wood` · `Terrain_Depleted`（可选） |
| 场景 | `Wall` · `Door_Locked` · `Door_Open` |
| 区域效果 | `Area_Steam` · `Area_Rot` · `Area_Heal` · `Area_Explosion` · `Area_Ring` |
| 掉落物 | `Pickup_Element` · `Pickup_Health` · `Pickup_Money` |
| 交互物 | `Pedestal_Base` · `Item_Default` · `Chest_Body` · `Chest_Lid` · `Spell_Card` · `Spell_CardGlow` |
| 传送门 | `Portal_Core` · `Portal_Ring` |

### 三个已经处理好的坑

1. **尺寸自动归一化**。占位图内部尺寸并不统一（方块 16px、圆形 32px、圆环 64px，PPU 都是 16，
   即分别是 1×1 / 2×2 / 4×4 单位），而正式美术的像素尺寸更是随意。
   `Visuals.FitScale` 统一按 `sprite.bounds` 反算 `localScale`，**让图恰好占满该单位的判定尺寸**，
   与图片自身多大无关。
   > 顺带修掉一个真 bug：旧代码里 `Make.Disc` 用 32px 圆形图却按直径缩放，
   > 所有圆形单位**一直渲染成直径的 2 倍**；区域圆环用的 64px 图更夸张，
   > **特效圈看起来是真实作用范围的 4 倍**。现在由 `T22` 盯着。
2. **配色不再污染美术**。某一槽位配了图之后，该处**不再乘占位色**，只保留 alpha
   （因为透明度还承担状态表达，例如地形剩余反应次数）。没配图的槽位行为完全不变。
3. **`FitToSize` 开关**。个别图想按原始像素尺寸显示（不缩放到判定框），
   在 SpriteSet 里取消勾选 `FitToSize` 即可。

### 整体选项（SpriteSet 资产上）

| 选项 | 作用 |
|---|---|
| `TileWalls` | 墙体改用 **Tiled 平铺**绘制（默认拉伸）。要求墙贴图的 **Mesh Type = Full Rect**，否则会报警告 |
| `TerrainAlphaByCharges` | 地形是否按剩余反应次数调整透明度（默认开；即使配了真图也保留这个反馈） |

### 还没做的

- **动画**：目前只支持单张静态图，没有 Animator / 序列帧接入点。
  后面要加的话，接入点是 `SpriteRenderer`——把 `Make.Visual(...)` 换成带 `Animator` 的版本即可。
- **九宫格 / 图集**：没做 `SpriteAtlas` 与 9-slice 支持。

### 手工验收（策划案要求的 60 秒链路）

1. Play，按 `F1` 把元素切到**火**
2. 走到一块**蓝色（水）**地形旁
3. 按 `Q` 用魔弹打那块水地形
4. → 生成**蒸汽区域**（浅灰圆盘 + 圆环），HUD 右侧「火×水 蒸汽区」计数 +1
5. 把怪引进蒸汽里 → 怪持续掉血

同理可验另外 5 条：**火×木 爆炸**、**水×木 腐烂减速**、**木×水 回血区**、**木×火 穿透+灼伤**、**水×火 穿透双倍**。
HUD 右侧的「元素反应验收（v2 矩阵）」面板会实时列出 7 条规则各自的触发次数——**只要把 7 行都打出 ✔，元素系统就算验收完毕。**
